== v1.0.31.3 — 2026-04-27

**Tous les PDF du marché sont désormais lisibles.** Plus besoin
de pré-traiter avec qpdf : crystal-pdf v0.3.6 lit les xref streams
PDF 1.5+ et les object streams, et crystal-combine-pdf préserve
correctement les images non-décodables (CCITTFaxDecode pour les
scans noir-blanc, DCTDecode pour les JPEG, JBIG2Decode, JPXDecode).

=== Changements

* Dépendance bumpée : `crystal-pdf` v0.3.5 → v0.3.6.
* `Merger#remap` respecte désormais `Stream#decoded` (nouveau
  drapeau crystal-pdf v0.3.6) :
** `decoded == true` → on supprime `/Filter` et `/DecodeParms`
   du dictionnaire (les octets sont clairs, le writer ne ré-encode
   pas).
** `decoded == false` → on PRÉSERVE `/Filter` et `/DecodeParms`
   (les octets sont encore encodés, on les recopie tels quels ; le
   prochain parser saura les décoder).

=== Pourquoi ça compte

Avant : un PDF source qui contenait une image scannée avec
`/Filter /CCITTFaxDecode` ressortait du merger comme un pavé gris.
Le scan était silencieusement corrompu parce que crystal-pdf
ne savait pas l'inverser, le merger croyait avoir des octets
clairs, et le reader suivant tentait d'appliquer le filtre sur du
contenu déjà décompressé.

Maintenant : tous les PDF testés sur le corpus
`tmp/2026-04-26--laguiole-messe` (16 fichiers : PDF 1.3 à 1.7,
LilyPond, Microsoft Word, scans CCITT, photos JPEG, partitions
Finale et Sibelius) ressortent du merger intacts.

=== Tests

64 specs verts (inchangés). Validation manuelle sur le corpus
`laguiole-messe` : assemblage complet sans warning, sans
exclusion manuelle, et le rendu visuel des partitions scannées
est préservé.

== v1.0.31.2 — 2026-04-27

**Mode déclaratif `.crystal-combine-pdf.yml`** — la nouvelle façon
recommandée d'assembler un livret. L'utilisateur lance
`crystal-combine-pdf --init` dans un dossier de PDFs ; un fichier YAML
est généré avec la liste, l'utilisateur réordonne / titre / commente
selon ses besoins, puis `crystal-combine-pdf` (sans argument) construit
le livret final.

=== Nouvelles commandes

* `crystal-combine-pdf --init` (`-i`) — génère un
  `.crystal-combine-pdf.yml` peuplé avec les `*.pdf` du dossier courant.
* `crystal-combine-pdf --refresh` (`-R`) — met à jour la liste `files:`
  : ajoute en fin les nouveaux PDF, commente les entrées dont le
  fichier a disparu (avec annotation `# disparu le YYYY-MM-DD`).
  *Préserve* commentaires, ordre courant et titres inline.
* `crystal-combine-pdf --recursive` (`-r`) — scan récursif des
  sous-dossiers (avec `--init` ou `--refresh`), parents d'abord puis
  sous-dossiers triés alphabétiquement.
* `crystal-combine-pdf --dir DIR` (`-d`) — cible un dossier différent
  du courant.
* `crystal-combine-pdf` (sans argument) — lit le YAML du dossier
  courant et produit le livret.

=== Fichier `.crystal-combine-pdf.yml`

Couvre tous les réglages d'assemblage :

* `output`, `title`, `author`, `duplex`
* `cover.mode` (`none` | `recto` | `recto-verso`),
  `cover.include_in_numbering`. Surcharge asymétrique via
  `cover.front` / `cover.back`.
* `numbering.enabled`, `numbering.global`, `numbering.partition`,
  `numbering.skip_pages`. Chaque couche : `enabled`, `format`,
  `style` (`plain` | `badge` | `circle` | `square` | `oval`),
  `position`, `font_size`, `color`, `margin`, `hide_when_single`.
* Section `toc:` (commentée par défaut — bookmarks et page TOC
  textuelle prévus pour v1.0.31.3).
* Section `watermark:` (commentée par défaut, déléguée à
  `crystal-watermark`).
* Liste `files:` avec forme courte `- foo.pdf` et forme longue
  `- foo.pdf: "Titre lisible"`. Préfixe `# - ` pour exclure une entrée.

=== Refonte du moteur de numérotation

`AdvancedNumberer` remplace l'ancien `Numberer` pour les builds
déclaratifs (l'ancien reste pour les sous-commandes historiques) :

* **15 positions cardinales** — `top-left/center/right`,
  `bottom-left/center/right`.
* **4 positions duplex-aware** — `outer-top`, `inner-top`,
  `outer-bottom`, `inner-bottom`. Quand `duplex: true`,
  `outer-*` = côté opposé à la reliure, `inner-*` = côté reliure ;
  les deux alternent par parité de page.
* **5 styles visuels** — `plain` (texte nu), `badge` (cadre arrondi
  gris pâle), `circle`, `square`, `oval`.
* **Couverture cover-aware** — quand `cover.include_in_numbering: false`,
  les `cover.front_pages` premières et `cover.back_pages` dernières
  pages ne sont pas numérotées et la numérotation démarre à 1 sur la
  première page de contenu. `%total%` reflète le total *utile*.

=== Filigrane

Section `watermark:` du YAML déléguée à `crystal-watermark` (nouvelle
dépendance, `~> 0.1`). Cinq styles supportés : `diagonal`, `tiled`,
`header`, `footer`, `center`. Réglages `text`, `font_size`, `color`,
`opacity`, `rotation`.

=== Validation préalable

`BookletBuilder` ouvre chaque PDF avant la fusion et liste tous les
fichiers non lisibles par `crystal-pdf` (xref streams PDF 1.5+,
filtres CCITTFaxDecode/DCTDecode) avec un message d'erreur clair et
des contournements suggérés (`qpdf --object-streams=disable`).

=== Reportés en v1.0.31.3

* **Bookmarks PDF** (`/Outlines`) — barre latérale navigable du lecteur.
* **Page TOC textuelle cliquable** — sommaire avec liens internes.
* Header de titre par fichier — stub présent dans la `Layer` mais pas
  encore rendu.

=== Tests

64 exemples (52 hérités + 12 nouveaux d'intégration : `--init`,
`--refresh`, scan récursif, build end-to-end avec
`cover.include_in_numbering`, watermark).

== v1.0.31.1 — 2026-04-26

**ISO compatibility with Ruby gem `combine_pdf` v1.0.31** — the
canonical entry points and the `PDF` instance API now mirror the
upstream gem one-to-one, so Ruby users can port their snippets
verbatim. Versioning adopts the `<gem-version>.<our-iteration>`
scheme (4th digit increments per additive Crystal-side iteration).

=== Module entry points

[source,crystal]
----
pdf = CombinePDF.new                 # ⇄ CombinePDF.new
pdf << CombinePDF.load("a.pdf")      # ⇄ CombinePDF.load(path)
pdf << CombinePDF.parse(some_bytes)  # ⇄ CombinePDF.parse(data)
----

=== `CombinePDF::PDF` instance API

* `pdf << other` — append (path or PDF), chainable
* `pdf >> other` — prepend (path or PDF), chainable
* `pdf.insert(position, other)` — insert at index
  (`-1` = append, `0` = prepend)
* `pdf.remove(page_index)` — remove a page (negative indices
  supported)
* `pdf.pages` — array of page references
* `pdf.page_count` — number of pages
* `pdf.new_page(mediabox, location)` — append/insert a blank page
  (default mediabox = US Letter `[0, 0, 612, 792]`)
* `pdf.title=` / `pdf.author=` — written to `/Info` on save
* `pdf.number_pages(partitions, options)` — in-place page
  numbering (booklet-aware)
* `pdf.save(path)` — write to disk
* `pdf.to_pdf` — return the PDF as `Bytes`

=== Crystal-specific bonuses (kept from v0.2)

* `CombinePDF.merge(inputs, output)`
* `CombinePDF.number(input, output, partitions, options)`
* `CombinePDF.assemble(inputs, output, options)` — merge + number
  in one shot

=== Implementation notes

* `CombinePDF::PDF` wraps the existing `Merger` ; ordering
  operations (insert/prepend/remove) reorder `merger.page_refs`
  in place — no object pool churn.
* `Merger#write` is now idempotent: a snapshot of `@objects` and
  `@next_id` is taken on entry and restored on exit, so calling
  `save` then `to_pdf` (or vice-versa) on the same instance
  produces deterministic byte streams.
* Two new `Merger` properties — `metadata_title`, `metadata_author`
  — feed the `/Info` dictionary when the high-level `PDF#title=`
  and `PDF#author=` setters are used.
* All internal references to the `crystal-pdf` shard now use the
  fully-qualified `::PDF::*` form to avoid being shadowed by the
  new `CombinePDF::PDF` class.

== v0.2.0 — 2026-04-26

**Multi-PDF merging shipped — the headline feature.** This is what
the upstream Ruby gem `combine_pdf` is famous for, and it's now
available in Crystal too.

Three new building blocks :

* `CombinePDF.merge(inputs : Array(String), output : String)` —
  concatenates several PDFs into one. Pages are taken in input
  order. Object IDs are renumbered to avoid collisions between
  sources, references rewritten recursively (Dictionary → Array →
  Stream metadata). MediaBox of every page preserved (mix A4 +
  Letter + A3 cohabits without normalisation).
* `CombinePDF.assemble(inputs, output, options)` — end-to-end
  booklet assembly: merges N PDFs, then numbers the result with
  partition sizes auto-detected from the input page counts. The
  workflow for a music score booklet of partitions of 1, 2 or N
  pages.
* CLI sub-commands `merge` and `assemble` :

  ----
  crystal-combine-pdf merge p1.pdf p2.pdf p3.pdf -o livret.pdf
  crystal-combine-pdf assemble p1.pdf p2.pdf p3.pdf -o livret.pdf
  ----

Implementation details :

* New `CombinePDF::Merger` class : reads each source via
  `PDF::Reader`, forces lazy materialisation of every indirect
  object via `Reader#resolve` over the whole xref, then renumbers
  & remaps recursively.
* New `CombinePDF::MergedDocumentWriter` : minimal PDF writer
  (header + indirect objects + xref + trailer). Bypasses
  `PDF::Document` because the latter is coupled to its in-memory
  pages and doesn't apply to external page injection.
* Dropped `/Filter`, `/DecodeParms`, `/Length` from copied stream
  dicts — the Reader stores decoded bytes but leaves the original
  filter declaration, which would make the next parser try to
  Flate-decode already-clear bytes.
* No deduplication of common resources (fonts, images) yet — the
  output is correct but slightly larger than what an optimising
  merger would produce. Targeted for v0.3.

Tests : 13 examples (2 unit + 11 integration), all green via real
`PDF::Reader.open` round-trips.

== v0.1.1 — 2026-04-25

Tightens the integration test suite and removes the v0.1.0
limitation note about re-parsing the output: `crystal-pdf` v0.3.4
fixed the byte-vs-char offset bug in `find_xref_offset`, so the
incremental update PDFs produced by the Numberer can now be
re-opened cleanly via `PDF::Reader.open`.

* Integration specs now drive their assertions through the real
  reader (page count + per-page MediaBox) instead of byte-level
  pattern counting. Net effect: stronger guarantees with fewer
  lines of test code.
* No behavioural change for end users — the Numberer output is
  byte-identical between v0.1.0 and v0.1.1.

== v0.1.0 — 2026-04-25

First public release. Pure-Crystal PDF page numbering, designed for
booklet assembly use cases (music score collections, course handouts,
…). Inspired by the Ruby gem
https://github.com/boazsegev/combine_pdf[combine_pdf] — fixes its
US Letter coordinate hardcoding and adds *partition-aware*
intra-numbering, which the upstream gem does not support.

* **Global page numbering** in the bottom-right corner, format
  customisable via `Options#global_format` (placeholders `%page%`
  and `%total%`, default `"%page%/%total%"`).
* **Intra-partition numbering** in the top-left corner, format
  customisable via `Options#partition_format`. Shown only when the
  partition spans more than one page (configurable via
  `hide_partition_when_single`).
* **A4-aware**, Letter-aware, A3-aware: coordinates are derived
  from each page's actual `MediaBox`, no per-format flag needed.
* **Skip pages** option (e.g. `--skip 1` to leave the cover
  unmarked).
* CLI sub-command `number` with short and long flags for every
  option.
* API: `CombinePDF.number(input, output, partitions, options)`.
* Bilingual README (EN + FR), CHANGELOG bilingue, ameba lint, CI
  GitHub Actions.
