== v1.0.31.21 — 2026-05-02

=== Added

* **`init --profile NAME`** : 5 profils prédéfinis qui ajustent les
  défauts du YAML généré au cas d'usage cible. Le shard n'est plus
  exclusivement orienté livret musical.
+
[cols="1,3"]
|===
| Profil | Cible

| `booklet` *(défaut)*
| Livret musical / liturgique. `oval` bottom-right (`• N / T •` 13 pt),

| `book`

  hardcodées dans le générateur YAML.

  exposée comme API publique. Lève `ArgumentError` pour un nom
  inconnu.
* Le YAML généré annote dans son en-tête le profil utilisé
  (`# Généré par crystal-combine-pdf init --profile <name>`).

Aucune rupture. Sans `--profile`, on conserve les défauts historiques
(profil `booklet`). Les YAML existants ne sont pas affectés.

== v1.0.31.20 — 2026-04-29

=== Fixed

* **Combined PDF was massively bloated.** A real-world test (a Mass
  booklet with 13 input PDFs totaling ~3.5 MB) produced a ~21 MB
  output — a ~6× bloat. Cause: when `Merger#remap` copies a stream
  that the parser had decoded (`Stream#decoded == true`, typical
  case for FlateDecode payloads — fonts, images, content streams),
  it stripped `/Filter` and `/DecodeParms` correctly but did NOT
  attach a fresh Flate filter. The decompressed bytes were then
  written verbatim by the writer (no compression applied), bloating
  the output to roughly the sum of decoded sizes.
* `Merger#remap` now attaches a `::PDF::Filters::Flate` filter to
  every decoded stream it copies. The writer recompresses on output.
  Same Mass booklet now produces a 2.6 MB output — *smaller* than
  the sum of inputs (uniform Flate compression ≥ many sources'
  original encoding). No visual change.
* Three integration specs that relied on `File.read(output_path)` to
  surface literal substrings (` 1 / 5 `, `Mon Recueil`, …) updated
  to use a new `SpecHelper.pdf_decoded_text` helper that walks
  `PDF::Reader#content_streams` (decoded form). Annotation tests
  still use raw bytes (annotations live in page dictionaries, not
  content streams).

== v1.0.31.19 — 2026-04-29

=== Fixed

* **Numbering rendered upside-down or invisible on some pages.**
  When a source PDF opens its content stream with a non-trivial CTM
  (e.g. `0.75 0 0 -0.75 0 841.92 cm` for a Y-flip + 0.75× scale,
  emitted by exporters that use top-left origin) at depth 0 of the
  graphics-state stack, that transformation persists into our
  appended overlay stream and our text comes out flipped and resized.
  Pages 6-7 (gloria, scale 0.24) became unreadable (~6.5 pt text);
  pages 1-2 (feuille-de-messe, scale 0.75) showed numbers
  upside-down.
* `AdvancedNumberer` now walks the prior content streams of each
  page, computes the cumulative depth-0 CTM, and prepends our
  overlay with its inverse (`q\\n<inverse> cm\\n... \\nQ`). When the
  cumulative is identity, no `cm` is emitted (no-op for
  well-formed PDFs).
* Implementation : minimal PDF tokenizer that handles `()` strings,
  `[]` arrays, `<<>>` dicts, `%` comments and tracks q/Q depth.

== v1.0.31.18 — 2026-04-29

=== Fixed

* **`refresh` adds new entries in the wrong place.** The end-of-section
  detection in `update_files_section` was over-greedy: it consumed
  free comments AFTER the `files:` entries (typically the
  `# ─── Format de page ───` delimiter and its block) as part of the
  section. New entries then landed at the bottom of that comment
  block, immediately before `paper_size:`. Fixed by tracking the
  *last* file-entry line and stopping at the first column-0
  free-comment delimiter (`# ─── Section ───`) or other top-level
  YAML key. Indented intra-section comments (column ≥ 2) are still
  preserved.
* **`refresh` does not propagate folder rename to `output:`.** When
  the folder is renamed, the canonical PDF output name should follow.
  `output:` is now updated to `<dir-basename>.pdf` whenever the new
  basename differs. `title:` follows only when it was auto-generated
  (i.e. equal to the previous output basename) — custom titles are
  preserved.
* **`refresh` lists the built PDF as an input.** `scan_pdfs`
  unconditionally collected every `*.pdf` in the directory, including
  `<dir>.pdf` (the build product). It would then end up as the last
  entry of `files:`, making the next build self-include the previous
  build (recursive). Both the *old* and *new* `output:` basenames are
  now excluded from the input scan.

== v1.0.31.12 — 2026-04-28

**Drapeaux CLI pour `init`.** Le YAML généré peut désormais être
personnalisé directement à la création, sans passer par une
édition manuelle. Les sections optionnelles peuvent être :
* gardées en commentaires (état historique, défaut)
* activées d'emblée
* complètement omises pour un fichier compact

=== Drapeaux

[cols="1,3"]
|===
| Drapeau | Effet

| `--paper-size SIZE`
| `paper_size:` (a4 \| letter \| legal \| a3 \| a5 \| b5 \| executive \| WxH)

| `--duplex`
| `duplex: true` (recto-verso)

| `--title TEXT`
| Override le titre (défaut : nom du dossier)

| `--author TEXT`
| Override l'auteur (défaut : `git config user.name`)

| `--init-output FILE`
| Override le nom du PDF de sortie

| `--init-format FMT`
| Format global de numérotation
  (défaut : `"• %page% / %total% •"`)

| `--no-numbering`
| `numbering.enabled: false`

| `--cover MODE`
| `cover.mode:` (none \| recto \| recto-verso)

| `--toc`
| Active la page de titre + sommaire cliquable

| `--skip-toc`
| Omet entièrement la section TOC du YAML

| `--watermark TEXT`
| Active le filigrane avec ce texte

| `--skip-watermark`
| Omet entièrement la section filigrane

| `--header`
| Active le header de partition (titre du fichier en haut)

| `--skip-header`
| Omet entièrement la section header
|===

=== Exemples

[source,shell]
----
# Livret recto-verso US Letter, sans filigrane, avec TOC
crystal-combine-pdf init --duplex --paper-size letter \
                         --skip-watermark --toc

# Numérotation avec étoiles, titre custom, sans header
crystal-combine-pdf init --init-format "★ %page% / %total% ★" \
                         --title "Mes Partitions" --skip-header

# Filigrane "BROUILLON" sur un livret minimaliste
crystal-combine-pdf init --watermark BROUILLON --no-numbering
----

== v1.0.31.11 — 2026-04-27

**Dingbats Unicode dans les formats de numérotation.** Étoiles,
cœurs, coches, croix, flèches et ornements floraux sont désormais
rendus correctement dans les pastilles. Aucune police TTF
embarquée — on utilise ZapfDingbats, le Type1 standard PDF garanti
présent dans tous les viewers.

=== Exemples

[source,yaml]
----
format: "★ %page% / %total% ★"   # → ★ 6 / 12 ★
format: "♥ %page% / %total% ♥"   # → ♥ 6 / 12 ♥
format: "❖ %page% / %total% ❖"   # → ❖ 6 / 12 ❖
format: "✦ %page% / %total% ✦"   # → ✦ 6 / 12 ✦
format: "✓ %page% / %total% ✓"   # → ✓ 6 / 12 ✓
----

=== Dingbats supportés

[cols="1,3"]
|===
| Catégorie | Caractères mappés

| Étoiles
| ★ ☆ ✦ ✧ ✩ ✪ ✫ ✬ ✭ ✮ ✯ ✰

| Cœurs / cartes à jouer
| ♥ ❤ ♠ ♣ ♦

| Coches & croix
| ✓ ✔ ✗ ✘ ✚ ✙ ✛ ✜ ✝ ✞ ✟ ✠

| Flèches
| → ➡ ➤ ➢

| Ornements
| ✿ ❀ ❁ ❖ ❧

| Chiffres cerclés
| ➀ ➁ ➂ ➃ ➄ ➅ ➆ ➇ ➈ ➉
|===

(Liste complète : voir `CombinePDF::ZapfDingbats::UNICODE_TO_ZAPF`.)

=== Implémentation

* Nouveau module `CombinePDF::ZapfDingbats` :
** `dingbat?(ch)` : `true` si `ch` est mappable
** `codepoint_for(ch)` : codepoint ZapfDingbats (UInt8)
** `width(font_size)` : largeur (approximation 0.7em)
** `split_runs(text)` : découpe en runs Helvetica/Zapf
* `AdvancedNumberer#render_layer` itère sur les runs : pour
  chaque segment, switch de font (`/__CCP_HV__` ou
  `/__CCP_ZD__`) et écrit le texte. `Tj` avance automatiquement
  le curseur entre runs.
* `AdvancedNumberer#ensure_fonts_in_page_resources` injecte
  ZapfDingbats sous la clé `/__CCP_ZD__` quand un dingbat est
  détecté. Pas d'`Encoding` explicite : ZapfDingbats utilise sa
  propre encoding interne (codepoints 0x21-0xFE).

== v1.0.31.9 — 2026-04-27

**Centrage horizontal correct des pastilles + format de
numérotation pleinement personnalisable** (incluant tous les
symboles typographiques WinAnsi).

=== Centrage horizontal des pastilles

Avant : la pastille ovale entourait le texte de manière
asymétrique — toujours plus large à droite qu'à gauche. Cause :
`approx_text_width` calculait `text.size × 0.55 × font_size` ;
pour `- 6 / 12 -` à 13pt, ça donnait ~64pt alors que la vraie
largeur Helvetica est ~46pt. Le rect avait donc 18pt de blanc
à droite que le texte ne remplissait pas.

Maintenant : nouveau module **`CombinePDF::WinAnsi`** qui
embarque les largeurs AFM officielles d'Adobe pour Helvetica et
Helvetica-Bold (256 entrées chacune). `WinAnsi.text_width(...)`
calcule à ~1pt près. La pastille épouse précisément le texte.

=== Format personnalisable + symboles

Le format de couche acceptait déjà `%page%` et `%total%`. Mais
les caractères non-ASCII (€, •, †, …, ", —, etc.) étaient envoyés
au content stream en UTF-8 brut, donc rendus comme des séquences
de caractères Latin-1 cassés (« â‚¬ », « â€¢ » au lieu de « € »,
« • »).

Maintenant : `AdvancedNumberer` encode ses textes via
`WinAnsi.write` (le même helper qui sert à `TocBuilder`).
Tous les caractères Latin-1 + symboles typographiques WinAnsi
sont rendus correctement.

==== Symboles disponibles

Section dédiée dans le template `init` avec exemples :

[source,yaml]
----
format: "%page%/%total%"           # → 6/12
format: "%page% / %total%"         # → 6 / 12
format: "- %page% / %total% -"     # → - 6 / 12 - (par défaut)
format: "page %page% sur %total%"  # → page 6 sur 12
format: "« %page%/%total% »"       # → « 6/12 »
format: "• %page% / %total% •"     # → • 6 / 12 •
format: "† %page% †"               # → † 6 †
----

Caractères supportés : ASCII + Latin-1 (accents français
notamment) + symboles typographiques WinAnsi 0x80-0x9F (€ • † ‡
… ‹ › « » " " ' ' – — ™ ‰ Œ œ Š Ÿ ƒ ‚ „). Hors WinAnsi → `?`.

=== Refactor

* Module `CombinePDF::WinAnsi` extrait dans `winansi.cr` : `write`,
  `text_width`, `approx_width`, tables AFM Helvetica/Helvetica-Bold.
* `AdvancedNumberer.escape_pdf_string` et `approx_text_width`
  supprimés (devenus inutiles).
* `TocBuilder.write_winansi` migrera vers `WinAnsi.write` dans
  une itération ultérieure (pas refactorisé pour l'instant —
  encapsulé indépendamment).

== v1.0.31.8 — 2026-04-27

**Polish de la pastille ovale.** Deux raffinements remontés sur
l'assemblage de référence.

=== Centrage vertical correct dans la pastille

Avant : le texte apparaissait légèrement décalé vers le haut
dans l'oval, parce que le rectangle était positionné en partant
de la baseline `y` moins une approximation grossière du
descender (`0.22 × font_size`). Sur les pastilles 13pt c'était
un décalage d'environ 1 pt — visible à l'œil.

Maintenant : le rectangle est centré sur le centre visuel du
texte, calculé comme `baseline + cap_height / 2`. Pour
Helvetica, `cap_height ≈ 0.7 × font_size`, donc le centre
visuel est à `y + 0.35 × font_size`. Le texte tombe pile au
milieu de la pastille.

=== Format global par défaut avec le total

Avant : `format: "- %page% -"` → la pastille affichait juste
`- 6 -` sans contexte.

Maintenant : `format: "- %page% / %total% -"` → la pastille
affiche `- 6 / 12 -`. Quand un musicien tient une seule page
imprimée du livret, il sait combien de pages restent.

=== Tests

68 specs verts. Spec d'intégration mis à jour pour
`(- 1 / 5 -)` à la place de `(- 1 -)`.

== v1.0.31.6 — 2026-04-27

**Trois correctifs critiques** détectés sur un assemblage réel :
numérotation invisible sur certains PDF, `--refresh` qui corrompait
le YAML, et UX des sous-commandes améliorée.

=== Correctifs

==== Numérotation visible quel que soit le PDF source

Avant : sur certains PDF d'entrée (générés par MS Word, Pages,
LibreOffice…), les numéros de page étaient bien injectés dans
le content stream mais ne s'affichaient pas dans le viewer. Cause
trouvée : nos opérateurs `/Helvetica X Tf` référençaient une
police absente du dictionnaire `/Resources /Font` de la page.
Adobe Reader inférait silencieusement la police standard, mais
Preview (macOS), mupdf et plusieurs viewers Web refusaient.

Fix : `AdvancedNumberer` et `Numberer` injectent désormais une
entrée `/__CCP_HV__` (Helvetica WinAnsi Type1 standard) dans le
`/Resources /Font` de chaque page modifiée. Le content stream
référence ce nom unique, garanti sans collision avec les polices
existantes du PDF source. Les dictionnaires `/Resources` et
`/Font` partagés via référence indirecte sont copiés
superficiellement avant modification, pour ne pas contaminer
d'autres pages.

==== `--refresh` ne corrompt plus le YAML

Avant : après un `--refresh`, le `.crystal-combine-pdf.yml`
ressortait en une seule ligne géante (« boubligoulba »). Cause :
`String#lines` en Crystal supprime les `\n` finaux par défaut
(`chomp: true`), à l'inverse de Ruby. Les lignes étaient
concaténées sans séparateur lors de la ré-écriture.

Fix : `ConfigRefresher#update_files_section` utilise désormais
`raw.lines(chomp: false)` pour préserver les `\n` originaux.

==== Sous-commandes `init` / `refresh` / `build`

Trois nouvelles sous-commandes plus naturelles à taper que les
flags long :

[cols="1,1"]
|===
| Avant | Maintenant aussi

| `crystal-combine-pdf --init`
| `crystal-combine-pdf init`

| `crystal-combine-pdf --refresh`
| `crystal-combine-pdf refresh`

| `crystal-combine-pdf` (implicite)
| `crystal-combine-pdf build` (explicite)
|===

Les flags `-i` / `-R` et `--init` / `--refresh` restent
disponibles pour la rétro-compatibilité ; les sous-commandes ne
sont qu'un alias.

=== Tests

== v1.0.31.5 — 2026-04-27

**Format de page configurable.** Le shard générait jusqu'ici toutes
ses pages (TOC, pages blanches…) en A4 hardcodé. Cette version
expose un réglage `paper_size:` au niveau du document et permet de
choisir parmi les standards courants ou de fournir des dimensions
libres.

=== Configuration

[source,yaml]
----
# Au niveau du document (s'applique à toutes les pages générées) :
paper_size: a4    # a4 (défaut) | letter | legal | a3 | a5 | b5
                  # | executive | "WxH" en points (ex. "595x842")

# Override possible par section :
toc:
  page:
    enabled: true
    paper_size: ""  # vide = hérite du paper_size global
----

=== Implémentation

* `Config#paper_size` (chaîne, défaut `"a4"`).
* `Config.paper_dimensions(name)` : helper de classe qui renvoie
  `{width, height}` en points pour les standards reconnus
  (insensible à la casse) ou parse `"WxH"` libre.
* `Config::Toc::Page#paper_size` : override optionnel (chaîne vide
  = hérite du global).
* `TocBuilder` : les anciennes constantes `PAGE_WIDTH` et
  `PAGE_HEIGHT` deviennent des `getter` calculés au constructeur
  via `Config.paper_dimensions(resolve_paper_size)`.
* `Merger#insert_toc_page` accepte désormais `width: Float64` et
  `height: Float64` (defaut A4).
* Template `--init` documente le réglage avec la liste des valeurs
  acceptées.

=== Cas d'usage

Le réglage **n'affecte pas les PDF d'entrée** — un livret peut
mélanger A4, Letter et A3 librement, chaque page conservant sa

== v0.2.0 — 2026-04-26

**Multi-PDF merging shipped — the headline feature.** This is what
the upstream Ruby gem `combine_pdf` is famous for, and it's now
available in Crystal too.

Three new building blocks :

* `CombinePDF.merge(inputs : Array(String), output : String)` —
  concatenates several PDFs into one. Pages are taken in input
  order. Object IDs are renumbered to avoid collisions between
  sources, references rewritten recursively (Dictionary → Array →
  Stream metadata). MediaBox of every page preserved (mix A4 +
  Letter + A3 cohabits without normalisation).
* `CombinePDF.assemble(inputs, output, options)` — end-to-end
  booklet assembly: merges N PDFs, then numbers the result with
  partition sizes auto-detected from the input page counts. The
  workflow for a music score booklet of partitions of 1, 2 or N
  pages.
* CLI sub-commands `merge` and `assemble` :

  ----
  crystal-combine-pdf merge p1.pdf p2.pdf p3.pdf -o livret.pdf
  crystal-combine-pdf assemble p1.pdf p2.pdf p3.pdf -o livret.pdf
  ----

Implementation details :

* New `CombinePDF::Merger` class : reads each source via
  `PDF::Reader`, forces lazy materialisation of every indirect
  object via `Reader#resolve` over the whole xref, then renumbers
  & remaps recursively.
* New `CombinePDF::MergedDocumentWriter` : minimal PDF writer
  (header + indirect objects + xref + trailer). Bypasses
  `PDF::Document` because the latter is coupled to its in-memory
  pages and doesn't apply to external page injection.
* Dropped `/Filter`, `/DecodeParms`, `/Length` from copied stream
  dicts — the Reader stores decoded bytes but leaves the original
  filter declaration, which would make the next parser try to
  Flate-decode already-clear bytes.
* No deduplication of common resources (fonts, images) yet — the
  output is correct but slightly larger than what an optimising
  merger would produce. Targeted for v0.3.

Tests : 13 examples (2 unit + 11 integration), all green via real
`PDF::Reader.open` round-trips.

== v0.1.0 — 2026-04-25

booklet assembly use cases (music score collections, course handouts,
…). Inspired by the Ruby gem
https://github.com/boazsegev/combine_pdf[combine_pdf] — fixes its
