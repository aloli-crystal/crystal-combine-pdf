== v1.0.31.38 — 2026-06-05

=== Ajouté

* **Sous-commandes `sign` / `verify`** — signer (PAdES) ou vérifier un
  document directement depuis combine-pdf, l'étape naturelle après
  `merge` / `assemble`. Fins relais vers le binaire `pdf-sign` de
  `aloli-crystal/pdf-signature` : tout ce qui suit le verbe lui est
  transmis tel quel (niveaux B-B…B-LTA, horodatage RFC 3161, LTV,
  PKCS#11/HSM), aucune duplication.
* **Sécurité** : la phrase de passe / le PIN est passé comme *nom* d'une
  variable d'environnement (jamais sa valeur).
* **Résolution du binaire** sûre : on cherche `pdf-sign` (via
  `$COMBINE_PDF_PDFSIG` ou le `PATH`), jamais le `pdfsig` de poppler.
  Nouveau module `CombinePDF::Signer`.

== v1.0.31.26 — 2026-05-06

=== Corrigé

* **Diagnostic précis des PDFs chiffrés** — au lieu d'un cryptique
  `Invalid header` (levé par zlib quand il tente de décompresser
  des octets chiffrés RC4/AES), le message d'erreur indique
  désormais clairement la nature du problème :
+
[source]
----
Erreur : Fichiers non lisibles :
  - partageons-le-pain.pdf
    → chiffré — PDF chiffré : Filter=Standard, algorithme=RC4 128-bit, R=3.
      Le déchiffrement n'est pas encore supporté par ce shard.
----
+
S'appuie sur la nouvelle exception `PDF::EncryptedPdfError` du
shard `aloli-crystal/pdf` v0.3.9. Détecte tous les niveaux de
chiffrement standard (RC4 40 / 128 bit, AES-128, AES-256).
+
*Cas typique attrapé* : « owner-only protection » des PDFs
Office / Acrobat avec restrictions de copie/édition mais sans
mot de passe utilisateur (`pdfinfo` affiche souvent
`Encrypted: no` sur ces fichiers).

=== Modifié

* Bump dépendance `aloli-crystal/pdf ~> 0.3.7` → `~> 0.3.9`.

== v1.0.31.25 — 2026-05-06

=== Ajouté

* **Sous-commande `crystal-combine-pdf gs FICHIER.pdf`** — normalise
  un PDF via Ghostscript, court-circuit complet du parser pdf
  interne. Utile quand un PDF mal formé (typique : PDF linéarisé
  Acrobat ancien avec stream zlib invalide) refuse d'être lu par
  le shard.
+
[source,shell]
----
crystal-combine-pdf gs fichier.pdf            # → fichier-normalised.pdf
crystal-combine-pdf gs fichier.pdf -i         # in-place
crystal-combine-pdf gs fichier.pdf -i --backup
crystal-combine-pdf gs fichier.pdf -o sortie.pdf
----
+
Délègue à `aloli-crystal/ghostscript` avec
`PDFSETTINGS=/default` (préserve la qualité, réécrit la
structure). Erreur claire si `gs` n'est pas installé, avec
commandes d'installation par OS.

=== Modifié

* **Message d'erreur `Fichiers non lisibles`** mis à jour pour
  proposer la nouvelle sous-commande `gs` en première option de
  contournement (au lieu de la commande `gs` brute, plus
  complexe à recopier). La commande gs reste documentée comme
  alternative pour qui veut.

== v1.0.31.22 — 2026-05-02

=== Ajouté

* **`crystal-combine-pdf compress FICHIER.pdf [-o SORTIE.pdf | -i]`** :
  réduit la taille d'un PDF unique en pur Crystal (sans dépendance
  réseau ni service en ligne).
+
Stratégie :
+
1. **Recompression Flate** uniforme via le `Merger` (depuis v1.0.31.20).
2. **Garbage collection** implicite : seuls les objets atteignables
   depuis le `/Catalog` sont copiés.
3. **Métadonnées rafraîchies** : `Producer` mis à jour, `Title`/
   `Author` préservés.
+
Gain typique 30-80 % selon le profil de compression d'origine.
Sortie typique :
+
[source]
----
$ crystal-combine-pdf compress kyrie.pdf
✓ 355,1 Ko → 266,6 Ko (24,9 %)
  pages: 1
  écrit dans : kyrie-compressed.pdf
----
+
Drapeaux :
+
* `-o SORTIE.pdf` : chemin de sortie explicite (défaut :
  `<input>-compressed.pdf`).
* `-i` / `--in-place` : réécrit le fichier d'entrée via un
  fichier temporaire atomique.
* `--backup` : avec `-i`, conserve l'original sous `.bak`.
+
*Limitations* (v1) : pas de downsampling d'images (300 DPI → 150 DPI),
pas de recompression JPEG, pas de subsetting de polices. Pour ces
optimisations, un futur flag `--deep` déléguera à
`aloli-crystal/ghostscript`.
* API : `CombinePDF.compress(input, output, backup: false)` retourne
  un `Compressor::Result` avec `before`, `after`, `pages` et
  `reduction_percent`.
* `Compressor::Result#to_s` formate joliment les tailles
  (Ko / Mo / pourcentage).

== v1.0.31.20 — 2026-04-29

=== Corrigé

* **PDF combiné massivement gonflé.** Cas réel (livret de messe avec
  13 PDFs en entrée totalisant ~3,5 Mo) : sortie ~21 Mo, soit un
  facteur ~6× de bloat. Cause : quand `Merger#remap` copie un
  stream que le parser a décodé (`Stream#decoded == true`, cas
  typique des payloads FlateDecode — polices, images, content
  streams), il supprimait correctement `/Filter` et `/DecodeParms`
  mais n'attachait PAS de nouveau filtre Flate. Les octets
  décompressés étaient alors écrits tels quels par le writer
  (aucune compression), gonflant la sortie à la somme des tailles
  décodées.
* `Merger#remap` attache désormais un `::PDF::Filters::Flate` à
  chaque stream décodé qu'il copie. Le writer recompresse à
  l'écriture. Le même livret produit maintenant une sortie de
  2,6 Mo — *plus petite* que la somme des entrées (la compression
  Flate uniforme bat parfois l'encodage d'origine). Aucun
  changement visuel.
* Trois specs d'intégration qui s'appuyaient sur
  `File.read(output_path)` pour matcher des sous-chaînes littérales
  (` 1 / 5 `, `Mon Recueil`, …) sont mises à jour pour utiliser un
  nouvel helper `SpecHelper.pdf_decoded_text` qui parcourt
  `PDF::Reader#content_streams` (forme décodée). Les tests
  d'annotations continuent d'utiliser les octets bruts (les
  annotations vivent dans le dictionnaire de page, pas dans les
  content streams).

== v1.0.31.19 — 2026-04-29

=== Corrigé

* **Numérotation rendue à l'envers ou invisible sur certaines pages.**
  Quand un PDF source ouvre son content stream avec une CTM non
  triviale (par ex. `0.75 0 0 -0.75 0 841.92 cm` pour un Y-flip +
  scale 0.75×, émis par des exporters qui utilisent l'origine
  top-left) à profondeur 0 de la pile graphics-state, cette
  transformation persiste dans notre overlay ajouté par-dessus et
  notre texte sort flippé et redimensionné. Les pages 6-7 (gloria,
  scale 0.24) devenaient illisibles (~6,5 pt) ; les pages 1-2
  (feuille-de-messe, scale 0.75) affichaient les numéros à l'envers.
* `AdvancedNumberer` parcourt désormais les content streams existants
  de chaque page, calcule la CTM cumulée à profondeur 0, et préfixe
  notre overlay avec son inverse (`q\\n<inverse> cm\\n... \\nQ`).
  Quand la CTM cumulée est l'identité, aucun `cm` n'est émis (no-op
  pour les PDFs bien formés).
* Implémentation : tokeniseur PDF minimaliste qui gère les chaînes
  `()`, les arrays `[]`, les dicts `<<>>`, les commentaires `%` et
  suit la profondeur q/Q.

== v1.0.31.18 — 2026-04-29

=== Corrigé

* **`refresh` ajoute les nouvelles entrées au mauvais endroit.** La
  détection de fin de section dans `update_files_section` était trop
  gloutonne : elle consommait les commentaires libres APRÈS les
  entrées `files:` (typiquement le délimiteur `# ─── Format de page ───`
  et son bloc) comme faisant partie de la section. Les nouvelles
  entrées s'insèraient alors en bas de ce bloc commentaire, juste
  avant `paper_size:`. Corrigé en suivant la *dernière* entrée de
  fichier et en s'arrêtant au premier délimiteur libre à colonne 0
  (`# ─── Section ───`) ou autre clé YAML top-level. Les commentaires
  intra-section indentés (colonne ≥ 2) restent préservés.
* **`refresh` ne propage pas le renommage de dossier à `output:`.**
  Quand le dossier est renommé, le nom canonique du PDF de sortie
  doit suivre. `output:` est désormais mis à jour vers
  `<basename-dossier>.pdf` quand le nouveau basename diffère.
  `title:` ne suit que s'il était auto-généré (i.e. égal à l'ancien
  basename de output) — les titres personnalisés sont préservés.
* **`refresh` liste le PDF buildé comme entrée.** `scan_pdfs`
  collectait inconditionnellement tous les `*.pdf` du dossier, y
  compris `<dossier>.pdf` (le produit du build). Il atterrissait
  alors comme dernière entrée de `files:`, faisant que le build
  suivant s'auto-incluait (récursif). Les basenames de `output:`
  *ancien* ET *nouveau* sont désormais exclus du scan.

== v1.0.31.12 — 2026-04-28

**Drapeaux CLI pour `init`.** Le YAML généré peut désormais être
personnalisé directement à la création, sans passer par une
édition manuelle. Les sections optionnelles peuvent être :
* gardées en commentaires (état historique, défaut)
* activées d'emblée
* complètement omises pour un fichier compact

=== Drapeaux

[cols="1,3"]
|===
| Drapeau | Effet

| `--paper-size SIZE`
| `paper_size:` (a4 \| letter \| legal \| a3 \| a5 \| b5 \| executive \| WxH)

| `--duplex`
| `duplex: true` (recto-verso)

| `--title TEXT`
| Override le titre (défaut : nom du dossier)

| `--author TEXT`
| Override l'auteur (défaut : `git config user.name`)

| `--init-output FILE`
| Override le nom du PDF de sortie

| `--init-format FMT`
| Format global de numérotation
  (défaut : `"• %page% / %total% •"`)

| `--no-numbering`
| `numbering.enabled: false`

| `--cover MODE`
| `cover.mode:` (none \| recto \| recto-verso)

| `--toc`
| Active la page de titre + sommaire cliquable

| `--skip-toc`
| Omet entièrement la section TOC du YAML

| `--watermark TEXT`
| Active le filigrane avec ce texte

| `--skip-watermark`
| Omet entièrement la section filigrane

| `--header`
| Active le header de partition (titre du fichier en haut)

| `--skip-header`
| Omet entièrement la section header
|===

=== Exemples

[source,shell]
----
# Livret recto-verso US Letter, sans filigrane, avec TOC
crystal-combine-pdf init --duplex --paper-size letter \
                         --skip-watermark --toc

# Numérotation avec étoiles, titre custom, sans header
crystal-combine-pdf init --init-format "★ %page% / %total% ★" \
                         --title "Mes Partitions" --skip-header

# Filigrane "BROUILLON" sur un livret minimaliste
crystal-combine-pdf init --watermark BROUILLON --no-numbering
----

== v1.0.31.11 — 2026-04-27

**Dingbats Unicode dans les formats de numérotation.** Étoiles,
cœurs, coches, croix, flèches et ornements floraux sont désormais
rendus correctement dans les pastilles. Aucune police TTF
embarquée — on utilise ZapfDingbats, le Type1 standard PDF garanti
présent dans tous les viewers.

=== Exemples

[source,yaml]
----
format: "★ %page% / %total% ★"   # → ★ 6 / 12 ★
format: "♥ %page% / %total% ♥"   # → ♥ 6 / 12 ♥
format: "❖ %page% / %total% ❖"   # → ❖ 6 / 12 ❖
format: "✦ %page% / %total% ✦"   # → ✦ 6 / 12 ✦
format: "✓ %page% / %total% ✓"   # → ✓ 6 / 12 ✓
----

=== Dingbats supportés

[cols="1,3"]
|===
| Catégorie | Caractères mappés

| Étoiles
| ★ ☆ ✦ ✧ ✩ ✪ ✫ ✬ ✭ ✮ ✯ ✰

| Cœurs / cartes à jouer
| ♥ ❤ ♠ ♣ ♦

| Coches & croix
| ✓ ✔ ✗ ✘ ✚ ✙ ✛ ✜ ✝ ✞ ✟ ✠

| Flèches
| → ➡ ➤ ➢

| Ornements
| ✿ ❀ ❁ ❖ ❧

| Chiffres cerclés
| ➀ ➁ ➂ ➃ ➄ ➅ ➆ ➇ ➈ ➉
|===

(Liste complète : voir `CombinePDF::ZapfDingbats::UNICODE_TO_ZAPF`.)

=== Implémentation

* Nouveau module `CombinePDF::ZapfDingbats` :
** `dingbat?(ch)` : `true` si `ch` est mappable
** `codepoint_for(ch)` : codepoint ZapfDingbats (UInt8)
** `width(font_size)` : largeur (approximation 0.7em)
** `split_runs(text)` : découpe en runs Helvetica/Zapf
* `AdvancedNumberer#render_layer` itère sur les runs : pour
  chaque segment, switch de font (`/__CCP_HV__` ou
  `/__CCP_ZD__`) et écrit le texte. `Tj` avance automatiquement
  le curseur entre runs.
* `AdvancedNumberer#ensure_fonts_in_page_resources` injecte
  ZapfDingbats sous la clé `/__CCP_ZD__` quand un dingbat est
  détecté. Pas d'`Encoding` explicite : ZapfDingbats utilise sa
  propre encoding interne (codepoints 0x21-0xFE).

== v1.0.31.9 — 2026-04-27

**Centrage horizontal correct des pastilles + format de
numérotation pleinement personnalisable** (incluant tous les
symboles typographiques WinAnsi).

=== Centrage horizontal des pastilles

Avant : la pastille ovale entourait le texte de manière
asymétrique — toujours plus large à droite qu'à gauche. Cause :
`approx_text_width` calculait `text.size × 0.55 × font_size` ;
pour `- 6 / 12 -` à 13pt, ça donnait ~64pt alors que la vraie
largeur Helvetica est ~46pt. Le rect avait donc 18pt de blanc
à droite que le texte ne remplissait pas.

Maintenant : nouveau module **`CombinePDF::WinAnsi`** qui
embarque les largeurs AFM officielles d'Adobe pour Helvetica et
Helvetica-Bold (256 entrées chacune). `WinAnsi.text_width(...)`
calcule à ~1pt près. La pastille épouse précisément le texte.

=== Format personnalisable + symboles

  internes et inadapté à l'injection de pages externes.
* Suppression de `/Filter`, `/DecodeParms`, `/Length` des
  dictionnaires de stream copiés — le Reader stocke les octets
  décodés mais laisse la déclaration de filtre originale, ce qui
  ferait que le prochain parseur tente de Flate-décoder des
  octets déjà clairs.
* Pas encore de déduplication des ressources communes (polices,
  images) — la sortie est correcte mais légèrement plus volumineuse
  qu'un merger optimisant. Visé pour la v0.3.

Tests : 13 exemples (2 unit + 11 intégration), tous verts via des
aller-retours `PDF::Reader.open` réels.

== v0.1.0 — 2026-04-25

Première version publique. Numérotation de pages PDF en Crystal pur,
conçue pour les cas d'usage d'assemblage de livret (recueils de
partitions musicales, fascicules de cours, …). Inspirée de la gem
Ruby https://github.com/boazsegev/combine_pdf[combine_pdf] — corrige
ses coordonnées hardcodées US Letter et ajoute la numérotation
*intra-partition*, que la gem amont ne supporte pas.

* **Numérotation globale** en bas à droite, format personnalisable
  via `Options#global_format` (substituts `%page%` et `%total%`,
  défaut `"%page%/%total%"`).
* **Numérotation intra-partition** en haut à gauche, format
  personnalisable via `Options#partition_format`. Affichée
  uniquement quand la partition fait plus d'une page (configurable
  via `hide_partition_when_single`).
* **A4-aware**, Letter-aware, A3-aware : coordonnées calculées à
  partir de la `MediaBox` réelle de chaque page, sans drapeau par
  format.
* Option **pages à exclure** (ex. `--skip 1` pour laisser la
  couverture intacte).
* Sous-commande CLI `number` avec drapeaux courts et longs pour
  toutes les options.
* API : `CombinePDF.number(input, output, partitions, options)`.
* README bilingue (EN + FR), CHANGELOG bilingue, lint ameba, CI
  GitHub Actions.
