== v1.0.31.6 — 2026-04-27

**Trois correctifs critiques** détectés sur un assemblage réel :
numérotation invisible sur certains PDF, `--refresh` qui
corrompait le YAML, et UX des sous-commandes améliorée.

=== Correctifs

==== Numérotation visible quel que soit le PDF source

Avant : sur certains PDF d'entrée (générés par MS Word, Pages,
LibreOffice…), les numéros de page étaient bien injectés dans
le content stream mais ne s'affichaient pas dans le viewer. Cause
trouvée : nos opérateurs `/Helvetica X Tf` référençaient une
police absente du dictionnaire `/Resources /Font` de la page.
Adobe Reader inférait silencieusement la police standard, mais
Preview (macOS), mupdf et plusieurs viewers Web refusaient.

Fix : `AdvancedNumberer` et `Numberer` injectent désormais une
entrée `/__CCP_HV__` (Helvetica WinAnsi Type1 standard) dans le
`/Resources /Font` de chaque page modifiée. Le content stream
référence ce nom unique, garanti sans collision avec les polices
existantes du PDF source. Les dictionnaires `/Resources` et
`/Font` partagés via référence indirecte sont copiés
superficiellement avant modification, pour ne pas contaminer
d'autres pages.

==== `--refresh` ne corrompt plus le YAML

Avant : après un `--refresh`, le `.crystal-combine-pdf.yml`
ressortait en une seule ligne géante (« boubligoulba »). Cause :
`String#lines` en Crystal supprime les `\n` finaux par défaut
(`chomp: true`), à l'inverse de Ruby. Les lignes étaient
concaténées sans séparateur lors de la ré-écriture.

Fix : `ConfigRefresher#update_files_section` utilise désormais
`raw.lines(chomp: false)` pour préserver les `\n` originaux.

==== Sous-commandes `init` / `refresh` / `build`

Trois nouvelles sous-commandes plus naturelles à taper que les
flags long :

[cols="1,1"]
|===
| Avant | Maintenant aussi

| `crystal-combine-pdf --init`
| `crystal-combine-pdf init`

| `crystal-combine-pdf --refresh`
| `crystal-combine-pdf refresh`

| `crystal-combine-pdf` (implicite)
| `crystal-combine-pdf build` (explicite)
|===

Les flags `-i` / `-R` et `--init` / `--refresh` restent
disponibles pour la rétro-compatibilité ; les sous-commandes ne
sont qu'un alias.

=== Tests

68 specs verts inchangés. Validation manuelle sur le scénario
exact rapporté par l'utilisateur (rename d'un PDF + refresh) sur
un dossier réel : YAML conservé propre, entrée disparue
commentée avec annotation date, nouvelle entrée ajoutée en fin.

== v1.0.31.5 — 2026-04-27

**Format de page configurable.** Le shard générait jusqu'ici toutes
ses pages (TOC, pages blanches…) en A4 hardcodé. Cette version
expose un réglage `paper_size:` au niveau du document et permet de
choisir parmi les standards courants ou de fournir des dimensions
libres.

=== Configuration

[source,yaml]
----
# Au niveau du document (s'applique à toutes les pages générées) :
paper_size: a4    # a4 (défaut) | letter | legal | a3 | a5 | b5
                  # | executive | "WxH" en points (ex. "595x842")

# Override possible par section :
toc:
  page:
    enabled: true
    paper_size: ""  # vide = hérite du paper_size global
----

=== Implémentation

* `Config#paper_size` (chaîne, défaut `"a4"`).
* `Config.paper_dimensions(name)` : helper de classe qui renvoie
  `{width, height}` en points pour les standards reconnus
  (insensible à la casse) ou parse `"WxH"` libre.
* `Config::Toc::Page#paper_size` : override optionnel (chaîne vide
  = hérite du global).
* `TocBuilder` : les anciennes constantes `PAGE_WIDTH` et
  `PAGE_HEIGHT` deviennent des `getter` calculés au constructeur
  via `Config.paper_dimensions(resolve_paper_size)`.
* `Merger#insert_toc_page` accepte désormais `width: Float64` et
  `height: Float64` (défaut A4).
* Template `--init` documente le réglage avec la liste des valeurs
  acceptées.

=== Cas d'usage

Le réglage **n'affecte pas les PDF d'entrée** — un livret peut
mélanger A4, Letter et A3 librement, chaque page conservant sa
`MediaBox` d'origine. Seules les pages **générées** par le shard
suivent `paper_size`.

=== Tests

68 specs verts (65 + 3 nouveaux : TOC en A4 défaut, en Letter
explicite, en custom `"500x700"` — chaque cas vérifie via
`PDF::Reader` que la première page a les bonnes dimensions).

== v1.0.31.4 — 2026-04-27

**Page de titre + sommaire cliquable.** Active la TOC dans le YAML
et le livret final ouvre désormais sur une vraie page de garde
avec liste des partitions et numéros de page — chaque ligne du
sommaire est un lien cliquable qui saute à la partition cible.

=== Configuration

[source,yaml]
----
toc:
  bookmarks: true
  page:
    enabled: true
    title: ""              # vide = utilise le `title:` du document
    subtitle: "Sommaire"
    show_author: true      # affiche "par <auteur>" si défini
    leader_dots: true      # pointillés entre titre et numéro
    title_font_size: 24
    subtitle_font_size: 16
    entry_font_size: 11
----

=== Implémentation

* Nouveau `CombinePDF::TocBuilder` qui produit le content stream
  PDF de la page TOC (titre, sous-titre, auteur, liste numérotée
  avec pointillés) + un dictionnaire `Annot` `/Subtype /Link`
  par entrée, avec destination `[page_ref /XYZ null null null]` —
  préserve la position et le zoom du viewer au saut.
* Nouveau `Merger#insert_toc_page(content, annotations)` qui
  alloue l'ID de la page TOC, ajoute le content stream et les
  annotations comme objets indirects, et insère la nouvelle page
  en tête de l'arbre `/Pages`.
* Polices Type1 standards (`Helvetica`, `Helvetica-Bold`,
  `Helvetica-Oblique`) déclarées dans le `/Resources` de la page
  TOC avec `/Encoding /WinAnsiEncoding` — pas d'embedding.
* `TocBuilder#write_winansi` convertit l'UTF-8 Crystal vers
  Windows-1252 byte-pour-byte avant l'encodage du content stream :
  ** ASCII et Latin-1 supplément encodés directement
  ** Caractères typographiques courants (apostrophes courbes,
     guillemets typographiques, em/en dashes, ellipsis, €, Œ, œ,
     Š, Ÿ, …) mappés sur leurs positions WinAnsi 0x80-0x9F
  ** Tout caractère hors WinAnsi remplacé par `?`

=== Numérotation

`AdvancedNumberer` accepte un nouveau paramètre `toc_pages : Int32`
(par défaut 0). Ces pages en tête sont :

* jamais numérotées (pas de couche globale ni partition)
* exclues du calcul du total `%total%` (le total reflète le
  contenu utile, pas la TOC ni les couvertures)

`BookletBuilder` passe `toc_pages = 1` quand `toc.page.enabled`.

=== Limitations

* Une seule page : si la liste déborde, elle est tronquée. La
  pagination de la TOC viendra dans une future version.
* Police Helvetica non-Unicode → glyphes en dehors de WinAnsi
  remplacés par `?`. Pour des partitions chinoises ou
  scandinaves nommées en non-latin, prévoir un fallback DejaVu
  ultérieurement.

=== Tests

65 specs verts (64 + 1 nouveau spec end-to-end qui vérifie la
présence du titre, du sommaire et d'au moins une annotation
`/Subtype /Link` dans le PDF produit).

== v1.0.31.3 — 2026-04-27

**Tous les PDF du marché sont désormais lisibles.** Plus besoin
de pré-traiter avec qpdf : crystal-pdf v0.3.6 lit les xref streams
PDF 1.5+ et les object streams, et crystal-combine-pdf préserve
correctement les images non-décodables (CCITTFaxDecode pour les
scans noir-blanc, DCTDecode pour les JPEG, JBIG2Decode, JPXDecode).

=== Changements

* Dépendance bumpée : `crystal-pdf` v0.3.5 → v0.3.6.
* `Merger#remap` respecte désormais `Stream#decoded` (nouveau
  drapeau crystal-pdf v0.3.6) :
** `decoded == true` → on supprime `/Filter` et `/DecodeParms`
   du dictionnaire (les octets sont clairs, le writer ne ré-encode
   pas).
** `decoded == false` → on PRÉSERVE `/Filter` et `/DecodeParms`
   (les octets sont encore encodés, on les recopie tels quels ; le
   prochain parser saura les décoder).

=== Pourquoi ça compte

Avant : un PDF source qui contenait une image scannée avec
`/Filter /CCITTFaxDecode` ressortait du merger comme un pavé gris.
Le scan était silencieusement corrompu parce que crystal-pdf
ne savait pas l'inverser, le merger croyait avoir des octets
clairs, et le reader suivant tentait d'appliquer le filtre sur du
contenu déjà décompressé.

Maintenant : tous les PDF testés sur le corpus
`tmp/2026-04-26--laguiole-messe` (16 fichiers : PDF 1.3 à 1.7,
LilyPond, Microsoft Word, scans CCITT, photos JPEG, partitions
Finale et Sibelius) ressortent du merger intacts.

=== Tests

64 specs verts (inchangés). Validation manuelle sur le corpus
`laguiole-messe` : assemblage complet sans warning, sans
exclusion manuelle, et le rendu visuel des partitions scannées
est préservé.

== v1.0.31.2 — 2026-04-27

**Mode déclaratif `.crystal-combine-pdf.yml`** — la nouvelle façon
recommandée d'assembler un livret. L'utilisateur lance
`crystal-combine-pdf --init` dans un dossier de PDF ; un fichier YAML
est généré avec la liste, l'utilisateur réordonne / titre / commente
selon ses besoins, puis `crystal-combine-pdf` (sans argument)
construit le livret final.

=== Nouvelles commandes

* `crystal-combine-pdf --init` (`-i`) — génère un
  `.crystal-combine-pdf.yml` peuplé avec les `*.pdf` du dossier courant.
* `crystal-combine-pdf --refresh` (`-R`) — met à jour la liste `files:`
  : ajoute en fin les nouveaux PDF, commente les entrées dont le
  fichier a disparu (avec annotation `# disparu le YYYY-MM-DD`).
  *Préserve* commentaires, ordre courant et titres inline.
* `crystal-combine-pdf --recursive` (`-r`) — scan récursif des
  sous-dossiers (avec `--init` ou `--refresh`), parents d'abord puis
  sous-dossiers triés alphabétiquement.
* `crystal-combine-pdf --dir DIR` (`-d`) — cible un dossier différent
  du courant.
* `crystal-combine-pdf` (sans argument) — lit le YAML du dossier
  courant et produit le livret.

=== Fichier `.crystal-combine-pdf.yml`

Couvre tous les réglages d'assemblage :

* `output`, `title`, `author`, `duplex`
* `cover.mode` (`none` | `recto` | `recto-verso`),
  `cover.include_in_numbering`. Surcharge asymétrique via
  `cover.front` / `cover.back`.
* `numbering.enabled`, `numbering.global`, `numbering.partition`,
  `numbering.skip_pages`. Chaque couche : `enabled`, `format`,
  `style` (`plain` | `badge` | `circle` | `square` | `oval`),
  `position`, `font_size`, `color`, `margin`, `hide_when_single`.
* Section `toc:` (commentée par défaut — bookmarks et page TOC
  textuelle prévus pour v1.0.31.3).
* Section `watermark:` (commentée par défaut, déléguée à
  `crystal-watermark`).
* Liste `files:` avec forme courte `- foo.pdf` et forme longue
  `- foo.pdf: "Titre lisible"`. Préfixe `# - ` pour exclure une entrée.

=== Refonte du moteur de numérotation

`AdvancedNumberer` remplace l'ancien `Numberer` pour les builds
déclaratifs (l'ancien reste pour les sous-commandes historiques) :

* **15 positions cardinales** — `top-left/center/right`,
  `bottom-left/center/right`.
* **4 positions duplex-aware** — `outer-top`, `inner-top`,
  `outer-bottom`, `inner-bottom`. Quand `duplex: true`,
  `outer-*` = côté opposé à la reliure, `inner-*` = côté reliure ;
  les deux alternent par parité de page.
* **5 styles visuels** — `plain` (texte nu), `badge` (cadre arrondi
  gris pâle), `circle`, `square`, `oval`.
* **Couverture cover-aware** — quand `cover.include_in_numbering: false`,
  les `cover.front_pages` premières et `cover.back_pages` dernières
  pages ne sont pas numérotées et la numérotation démarre à 1 sur la
  première page de contenu. `%total%` reflète le total *utile*.

=== Filigrane

Section `watermark:` du YAML déléguée à `crystal-watermark` (nouvelle
dépendance, `~> 0.1`). Cinq styles supportés : `diagonal`, `tiled`,
`header`, `footer`, `center`. Réglages `text`, `font_size`, `color`,
`opacity`, `rotation`.

=== Validation préalable

`BookletBuilder` ouvre chaque PDF avant la fusion et liste tous les
fichiers non lisibles par `crystal-pdf` (xref streams PDF 1.5+,
filtres CCITTFaxDecode/DCTDecode) avec un message d'erreur clair et
des contournements suggérés (`qpdf --object-streams=disable`).

=== Reportés en v1.0.31.3

* **Bookmarks PDF** (`/Outlines`) — barre latérale navigable du lecteur.
* **Page TOC textuelle cliquable** — sommaire avec liens internes.
* Header de titre par fichier — stub présent dans la `Layer` mais pas
  encore rendu.

=== Tests

64 exemples (52 hérités + 12 nouveaux d'intégration : `--init`,
`--refresh`, scan récursif, build end-to-end avec
`cover.include_in_numbering`, filigrane).

== v1.0.31.1 — 2026-04-26

**Compatibilité ISO avec la gem Ruby `combine_pdf` v1.0.31** — les
points d'entrée canoniques et l'API d'instance `PDF` reflètent
désormais la gem amont un-pour-un, ce qui permet aux utilisateurs
Ruby de porter leurs extraits verbatim. Le versioning adopte le
schéma `<version-gem>.<itération-locale>` (le 4ᵉ chiffre s'incrémente
à chaque itération additive côté Crystal).

=== Points d'entrée du module

[source,crystal]
----
pdf = CombinePDF.new                 # ⇄ CombinePDF.new
pdf << CombinePDF.load("a.pdf")      # ⇄ CombinePDF.load(path)
pdf << CombinePDF.parse(some_bytes)  # ⇄ CombinePDF.parse(data)
----

=== API d'instance `CombinePDF::PDF`

* `pdf << other` — ajoute en fin (chemin ou PDF), chaînable
* `pdf >> other` — ajoute en tête (chemin ou PDF), chaînable
* `pdf.insert(position, other)` — insère à l'index donné
  (`-1` = fin, `0` = début)
* `pdf.remove(page_index)` — retire une page (indices négatifs
  pris en charge)
* `pdf.pages` — tableau des références de pages
* `pdf.page_count` — nombre de pages
* `pdf.new_page(mediabox, location)` — ajoute/insère une page
  blanche (mediabox par défaut = US Letter `[0, 0, 612, 792]`)
* `pdf.title=` / `pdf.author=` — écrits dans `/Info` à la
  sauvegarde
* `pdf.number_pages(partitions, options)` — numérotation en place
  (livret-aware)
* `pdf.save(path)` — écrit sur disque
* `pdf.to_pdf` — renvoie le PDF en `Bytes`

=== Bonus spécifiques Crystal (conservés depuis v0.2)

* `CombinePDF.merge(inputs, output)`
* `CombinePDF.number(input, output, partitions, options)`
* `CombinePDF.assemble(inputs, output, options)` — fusion +
  numérotation en une commande

=== Notes d'implémentation

* `CombinePDF::PDF` enveloppe le `Merger` existant ; les opérations
  d'ordonnancement (insert/prepend/remove) réorganisent
  `merger.page_refs` en place — pas de churn dans le pool d'objets.
* `Merger#write` est désormais idempotent : un instantané de
  `@objects` et `@next_id` est pris à l'entrée et restauré à la
  sortie, donc appeler `save` puis `to_pdf` (ou l'inverse) sur la
  même instance produit des flux d'octets déterministes.
* Deux nouvelles propriétés sur `Merger` — `metadata_title`,
  `metadata_author` — alimentent le dictionnaire `/Info` quand les
  setters de haut niveau `PDF#title=` et `PDF#author=` sont
  utilisés.
* Toutes les références internes à la shard `crystal-pdf` utilisent
  désormais la forme pleinement qualifiée `::PDF::*` pour éviter
  d'être masquées par la nouvelle classe `CombinePDF::PDF`.

== v0.2.0 — 2026-04-26

**Fusion multi-PDF livrée — la fonctionnalité phare.** C'est ce qui
fait la renommée de la gem Ruby `combine_pdf` en amont, c'est
maintenant disponible en Crystal aussi.

Trois nouvelles briques :

* `CombinePDF.merge(inputs : Array(String), output : String)` —
  concatène plusieurs PDF en un seul. Pages prises dans l'ordre
  d'entrée. Les IDs d'objets sont renumérotés pour éviter les
  collisions entre sources, les références sont réécrites
  récursivement (Dictionary → Array → metadata de Stream). La
  MediaBox de chaque page est préservée (un mix A4 + Letter +
  A3 cohabite sans normalisation).
* `CombinePDF.assemble(inputs, output, options)` — assemblage de
  livret bout-en-bout : fusionne N PDF, puis numérote le résultat
  avec des tailles de partition auto-détectées depuis le nombre
  de pages de chaque entrée. Le workflow type pour un recueil
  de partitions musicales contenant des morceaux de 1, 2 ou N
  pages.
* Sous-commandes CLI `merge` et `assemble` :

  ----
  crystal-combine-pdf merge p1.pdf p2.pdf p3.pdf -o livret.pdf
  crystal-combine-pdf assemble p1.pdf p2.pdf p3.pdf -o livret.pdf
  ----

Détails d'implémentation :

* Nouvelle classe `CombinePDF::Merger` : lit chaque source via
  `PDF::Reader`, force la matérialisation paresseuse de tous les
  objets indirects via `Reader#resolve` sur tout le xref, puis
  renumérote et remappe récursivement.
* Nouvel `CombinePDF::MergedDocumentWriter` : écrivain PDF
  minimaliste (en-tête + objets indirects + xref + trailer).
  Court-circuite `PDF::Document` qui est couplé à ses pages
  internes et inadapté à l'injection de pages externes.
* Suppression de `/Filter`, `/DecodeParms`, `/Length` des
  dictionnaires de stream copiés — le Reader stocke les octets
  décodés mais laisse la déclaration de filtre originale, ce qui
  ferait que le prochain parseur tente de Flate-décoder des
  octets déjà clairs.
* Pas encore de déduplication des ressources communes (polices,
  images) — la sortie est correcte mais légèrement plus volumineuse
  qu'un merger optimisant. Visé pour la v0.3.

Tests : 13 exemples (2 unit + 11 intégration), tous verts via des
aller-retours `PDF::Reader.open` réels.

== v0.1.0 — 2026-04-25

Première version publique. Numérotation de pages PDF en Crystal pur,
conçue pour les cas d'usage d'assemblage de livret (recueils de
partitions musicales, fascicules de cours, …). Inspirée de la gem
Ruby https://github.com/boazsegev/combine_pdf[combine_pdf] — corrige
ses coordonnées hardcodées US Letter et ajoute la numérotation
*intra-partition*, que la gem amont ne supporte pas.

* **Numérotation globale** en bas à droite, format personnalisable
  via `Options#global_format` (substituts `%page%` et `%total%`,
  défaut `"%page%/%total%"`).
* **Numérotation intra-partition** en haut à gauche, format
  personnalisable via `Options#partition_format`. Affichée
  uniquement quand la partition fait plus d'une page (configurable
  via `hide_partition_when_single`).
* **A4-aware**, Letter-aware, A3-aware : coordonnées calculées à
  partir de la `MediaBox` réelle de chaque page, sans drapeau par
  format.
* Option **pages à exclure** (ex. `--skip 1` pour laisser la
  couverture intacte).
* Sous-commande CLI `number` avec drapeaux courts et longs pour
  toutes les options.
* API : `CombinePDF.number(input, output, partitions, options)`.
* README bilingue (EN + FR), CHANGELOG bilingue, lint ameba, CI
  GitHub Actions.
