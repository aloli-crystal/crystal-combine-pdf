= crystal-combine-pdf
:toc: macro
:toclevels: 2

Portage Crystal ISO-compatible de la gem Ruby
https://github.com/boazsegev/combine_pdf[`combine_pdf`] v1.0.31.
Syntaxe drop-in pour les utilisateurs Ruby — `CombinePDF.new`,
`CombinePDF.load`, `CombinePDF.parse` plus l'API d'instance
`<<` / `>>` / `insert` / `remove` / `save` / `to_pdf` /
`number_pages` sont câblés et se comportent à l'identique.

Au-dessus de la gem nous livrons deux bonus spécifiques Crystal :

* **Numérotation des pages A4-aware** — corrige le bug amont de
  coordonnées hardcodées US Letter de `number_pages` ; les
  coordonnées sont calculées depuis la `MediaBox` réelle de chaque
  page.
* **Numérotation intra-partition** — celle qui permet à un livret
  de partitions musicales d'afficher « 1/4 », « 2/4 » sur une
  partition de 4 pages pendant que le « 3/12 » global reste en
  bas à droite.

== Démarrage rapide (API ISO, miroir de la gem Ruby)

[source,crystal]
----
require "crystal-combine-pdf"

# Construire un PDF vierge
pdf = CombinePDF.new

# Charger + ajouter deux PDF existants
pdf << CombinePDF.load("partition1.pdf")
pdf << CombinePDF.load("partition2.pdf")

# Optionnel : préfixer une page de garde
pdf >> CombinePDF.load("couverture.pdf")

# Optionnel : métadonnées
pdf.title  = "Recueil de partitions"
pdf.author = "Philippe Nénert"

# Optionnel : numéroter les pages (bonus spécifique Crystal)
pdf.number_pages

# Sauvegarder
pdf.save("livret.pdf")
----

== Pourquoi

La gem Ruby `combine_pdf` est l'outil de fait pour assembler des
livrets PDF. Son helper `number_pages` dessine le numéro de page à
des coordonnées hardcodées dérivées du US Letter (612 × 792 pt). Sur
A4 (595 × 842 pt), A4 asiatique ou A3, le numéro tombe plusieurs
centimètres à côté.

Au-delà du décalage de format, un livret de partitions assemblé — où
chaque partition (morceau) peut faire 1, 2 ou N pages — a besoin
d'une seconde couche de numérotation : un petit « 1/4 », « 2/4 », …
dans le coin de chaque page de la partition, pour que le musicien
sache quand tourner la page et combien il en reste dans le morceau
courant.

`crystal-combine-pdf` fait les deux, en Crystal pur, en lisant la
géométrie réelle de chaque `MediaBox`.

== Fonctionnalités (v0.1)

* **Numérotation globale** en bas à droite (format personnalisable,
  défaut `"N/T"`).
* **Numérotation intra-partition** en haut à gauche (format
  personnalisable, défaut `"n/t"`), affichée uniquement quand la
  partition fait plus d'une page (configurable).
* **A4-aware**, Letter-aware, A3-aware — coordonnées calculées depuis
  la `MediaBox` réelle de chaque page, sans drapeau par format.
* **Pages à exclure** (couvertures par ex.) : `--skip 1,2`.
* **Crystal pur**, binaire unique, pas de `pdftk`/`qpdf`/`pdftotext`
  dans le `$PATH`.

== Installation

Ajouter au `shard.yml` :

[source,yaml]
----
dependencies:
  crystal-combine-pdf:
    github: aloli-crystal/crystal-combine-pdf
    version: "~> 1.0.31"
----

puis lancer `shards install`.

Pour la CLI :

[source,shell]
----
git clone https://github.com/aloli-crystal/crystal-combine-pdf
cd crystal-combine-pdf
shards build --release
cp bin/crystal-combine-pdf ~/bin/   # ou utiliser crystal-bin-installer
----

== CLI

Trois sous-commandes : `number`, `merge`, `assemble`.

=== `assemble` — le workflow livret (le plus courant)

[source,shell]
----
# Prendre trois PDF de partitions, les fusionner, numéroter le
# résultat avec des tailles de partition auto-détectées (donc
# chaque partition reçoit son marquage intra-partition "1/4",
# "2/4" là où c'est pertinent).
crystal-combine-pdf assemble \
  partition1.pdf partition2.pdf partition3.pdf \
  -o livret.pdf
----

=== `merge` — concaténation pure, sans numérotation

[source,shell]
----
crystal-combine-pdf merge p1.pdf p2.pdf p3.pdf -o sortie.pdf
----

=== `number` — numéroter un PDF déjà assemblé

[source,shell]
----
# Défaut : format "N/T" en bas à droite.
crystal-combine-pdf number livret.pdf

# Idem, avec marquage intra-partition. Tailles données dans l'ordre
# 1-based des pages — la somme doit valoir le nombre total de pages.
# Ici : pages 1-4 = partition 1 (donc chacune marquée "1/4" à "4/4"),
# pages 5-6 = partition 2, page 7 = partition 3 (1 page → pas de
# marque intra-partition par défaut).
crystal-combine-pdf number livret.pdf --partitions 4,2,1

# Ne pas numéroter la couverture (page 1).
crystal-combine-pdf number livret.pdf --skip 1

# Format personnalisé et couleur rouge.
crystal-combine-pdf number livret.pdf \
  --global-format "Page %page% sur %total%" \
  --partition-format "(%page% / %total%)" \
  --color "0.7,0.0,0.0" \
  --font-size 12
----

=== Options

[cols="1,3"]
|===
| Option | Description

| `-o FICHIER`, `--output FICHIER`
| Chemin de sortie. Défaut : `<entrée>-numbered.pdf` à côté du
  fichier d'entrée.

| `--partitions N,N,…`
| Liste de tailles de partitions séparées par des virgules, dans
  l'ordre 1-based des pages. La somme doit égaler le nombre total
  de pages du PDF.

| `--skip PAGES`
| Liste de numéros de page (1-based) à laisser non numérotés
  (typique : `--skip 1` pour épargner la couverture).

| `--font-size TAILLE`
| Taille en points des numéros rendus. Défaut 10.

| `--margin PT`
| Marge depuis le bord de la page, en points. Défaut 24.

| `--color R,G,B`
| Triplet RGB, composantes 0.0 à 1.0. Défaut `0.2,0.2,0.2`.

| `--global-format FMT`
| Chaîne de format du numéro global. Substituts : `%page%`,
  `%total%`. Défaut `"%page%/%total%"`.

| `--partition-format FMT`
| Chaîne de format du numéro intra-partition. Mêmes substituts.
  Défaut `"%page%/%total%"`.

| `--show-single-partitions`
| Affiche le numéro intra-partition même quand la partition fait une
  seule page. Désactivé par défaut.

| `-h`, `--help`, `-v`, `--version`
| Standard.
|===

== API

=== API ISO (miroir de la gem Ruby)

[source,crystal]
----
require "crystal-combine-pdf"

# Points d'entrée du module
CombinePDF.new                  # => CombinePDF::PDF (vide)
CombinePDF.load(path : String)  # => CombinePDF::PDF (depuis fichier)
CombinePDF.parse(data : Bytes)  # => CombinePDF::PDF (depuis octets)

# API d'instance
pdf << other        # ajoute en fin (chemin ou PDF) — chaînable
pdf >> other        # ajoute en tête (chemin ou PDF) — chaînable
pdf.insert(position, other)  # position : Int32 (-1 = fin, 0 = début)
pdf.remove(page_index)       # indices négatifs pris en charge
pdf.pages                    # => Array(::PDF::Objects::Reference)
pdf.page_count               # => Int32
pdf.new_page(mediabox = [0, 0, 612, 792], location = -1)
pdf.title = "…"
pdf.author = "…"
pdf.number_pages(partitions, options)  # en place
pdf.save("sortie.pdf")
pdf.to_pdf  # => Bytes
----

=== Helpers bonus spécifiques Crystal

[source,crystal]
----
# Concaténation multi-PDF en une commande
CombinePDF.merge(["a.pdf", "b.pdf"], "sortie.pdf")

# Numéroter un PDF déjà assemblé sur disque
CombinePDF.number(
  input: "livret.pdf",
  output: "livret-numbered.pdf",
  partitions: [4, 2, 1],
  options: CombinePDF::Options.new(
    font_size: 11.0,
    color: {0.2, 0.2, 0.2},
    margin: 24.0,
    skip_pages: [1],
  ),
)

# Assemblage de livret bout-en-bout (fusion + numérotation avec
# tailles de partitions auto-détectées — chaque fichier d'entrée =
# une partition)
CombinePDF.assemble(
  inputs: ["partition1.pdf", "partition2.pdf", "partition3.pdf"],
  output: "livret.pdf",
)
----

== Limitations (v1.0.31.1)

* Pas de déduplication des ressources communes lors de la fusion —
  une police ou image embarquée dans N PDF source est copiée N fois
  dans la sortie. Résultat correct mais légèrement plus volumineux
  qu'un merger optimisant. Visé pour la v0.3.
* La numérotation est rendue avec le `Helvetica` standard Type1 (pas
  de police embarquée, pas d'Unicode au-delà des chiffres ASCII et
  du `/`).
* La sortie de `number` est une **mise à jour incrémentale** (spec
  PDF § 7.5.6) ; `merge` et `assemble` écrivent un PDF neuf depuis
  zéro. Les deux sont gérés correctement par `crystal-pdf::Reader`
  v0.3.4+ et tous les lecteurs PDF du marché.
