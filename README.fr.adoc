= combine-pdf
:toc: macro
:toclevels: 2

Portage Crystal ISO-compatible de la gem Ruby
https://github.com/boazsegev/combine_pdf[`combine_pdf`] v1.0.31.
Syntaxe drop-in pour les utilisateurs Ruby — `CombinePDF.new`,
`CombinePDF.load`, `CombinePDF.parse` plus l'API d'instance
`<<` / `>>` / `insert` / `remove` / `save` / `to_pdf` /
`number_pages` sont câblés et se comportent à l'identique.

Au-dessus de la gem nous livrons deux bonus spécifiques Crystal :

* **Numérotation des pages A4-aware** — corrige le bug amont de
  coordonnées hardcodées US Letter de `number_pages` ; les
  coordonnées sont calculées depuis la `MediaBox` réelle de chaque
  page.
* **Numérotation intra-partition** — celle qui permet à un livret
  de partitions musicales d'afficher « 1/4 », « 2/4 » sur une
  partition de 4 pages pendant que le « 3/12 » global reste en
  bas à droite.

== Démarrage rapide (mode déclaratif, recommandé pour les livrets)

Trois commandes pour assembler un dossier de PDF en livret :

[source,shell]
----
cd /chemin/vers/mes-partitions
combine-pdf init        # génère .combine-pdf.yml
$EDITOR .combine-pdf.yml  # réordonner, titrer, exclure
combine-pdf             # construit mes-partitions.pdf
----

Voir la section <<Mode déclaratif>> pour le détail du fichier
`.combine-pdf.yml`.

== Démarrage rapide (API ISO, miroir de la gem Ruby)

[source,crystal]
----
require "combine-pdf"

# Construire un PDF vierge
pdf = CombinePDF.new

# Charger + ajouter deux PDF existants
pdf << CombinePDF.load("partition1.pdf")
pdf << CombinePDF.load("partition2.pdf")

# Optionnel : préfixer une page de garde
pdf >> CombinePDF.load("couverture.pdf")

# Optionnel : métadonnées
pdf.title  = "Recueil de partitions"
pdf.author = "Philippe Nénert"

# Optionnel : numéroter les pages (bonus spécifique Crystal)
pdf.number_pages

# Sauvegarder
pdf.save("livret.pdf")
----

== Pourquoi

La gem Ruby `combine_pdf` est l'outil de fait pour assembler des
livrets PDF. Son helper `number_pages` dessine le numéro de page à
des coordonnées hardcodées dérivées du US Letter (612 × 792 pt). Sur
A4 (595 × 842 pt), A4 asiatique ou A3, le numéro tombe plusieurs
centimètres à côté.

Au-delà du décalage de format, un livret de partitions assemblé — où
chaque partition (morceau) peut faire 1, 2 ou N pages — a besoin
d'une seconde couche de numérotation : un petit « 1/4 », « 2/4 », …
dans le coin de chaque page de la partition, pour que le musicien
sache quand tourner la page et combien il en reste dans le morceau
courant.

`combine-pdf` fait les deux, en Crystal pur, en lisant la
géométrie réelle de chaque `MediaBox`.

== Fonctionnalités (v0.1)

* **Numérotation globale** en bas à droite (format personnalisable,
  défaut `"N/T"`).
* **Numérotation intra-partition** en haut à gauche (format
  personnalisable, défaut `"n/t"`), affichée uniquement quand la
  partition fait plus d'une page (configurable).
* **A4-aware**, Letter-aware, A3-aware — coordonnées calculées depuis
  la `MediaBox` réelle de chaque page, sans drapeau par format.
* **Pages à exclure** (couvertures par ex.) : `--skip 1,2`.
* **Crystal pur**, binaire unique, pas de `pdftk`/`qpdf`/`pdftotext`
  dans le `$PATH`.

== Mode déclaratif

La façon recommandée d'assembler un livret de partitions, de
chants, ou n'importe quelle liste de PDF.

=== Commandes

[source,shell]
----
combine-pdf init [-r] [--profile NOM] [--user-config CHEMIN]
  Initialise .combine-pdf.yml dans le dossier courant.
  -r scanne aussi les sous-dossiers (parents d'abord, puis alpha).
  --profile : booklet (défaut) | book | report | slides | minimal
  --user-config : chemin custom (défaut : ~/.combine-pdf.yml)

combine-pdf refresh [-r]
  Rafraîchit la liste `files:` du YAML existant : ajoute en fin
  les nouveaux PDF, commente les entrées dont le fichier a
  disparu. Préserve commentaires, ordre courant et titres inline.

combine-pdf build
combine-pdf
  Sans sous-commande : lit .combine-pdf.yml du dossier
  courant, assemble le livret, applique numérotation et
  filigrane, écrit la sortie.

combine-pdf compress FICHIER.pdf [-o SORTIE.pdf | -i] [--deep]
  Réduit la taille d'un PDF unique (recompression Flate + GC).
  --deep délègue à ghostscript pour le downsampling d'images.
  -i : in-place, --backup : conserve l'original sous .bak.

combine-pdf -d, --dir DOSSIER
  Option commune : cible un dossier différent du courant.
----

=== Exemple de `.combine-pdf.yml`

[source,yaml]
----
output: mes-partitions.pdf
title:  "Mes Partitions"
author: "Philippe Nénert"

duplex: true              # recto-verso

cover:
  mode: recto-verso       # none | recto | recto-verso
  include_in_numbering: false

numbering:
  enabled: true
  global:
    enabled: true
    format: "%page%/%total%"
    style: badge          # plain | badge | circle | square | oval
    position: outer-bottom
    font_size: 10
    color: "#333333"
    margin: 24
  partition:
    enabled: true
    format: "%page%/%total%"
    style: plain
    position: outer-top
    font_size: 9
    color: "#666666"
    hide_when_single: true
  skip_pages: []

# watermark:
#   text: "Confidentiel"
#   style: diagonal       # diagonal | tiled | header | footer | center
#   font_size: 48
#   color: "#cccccc"
#   opacity: 0.15
#   rotation: 45

# Chiffrement de la SORTIE (livret protégé par mot de passe).
# encrypt:
#   enabled: true
#   level: aes_256          # rc4_128 | aes_128 | aes_256
#   user_password: ""       # ouverture (vide = pas de password à l'open)
#   owner_password: ""      # restrictions (vide = identique à user)
#   permissions: [print, copy, modify, annotate]

# Mot de passe ESSAYÉ sur les PDFs sources chiffrés (cas global).
# Surchargeable au cas par cas dans `files:` ci-dessous.
# input_password: ""

files:
  - couverture.pdf
  - partition1.pdf: "Allegro — C. Debussy"
  - partition2.pdf: "Adagio — F. Chopin"
  # - brouillon-2025.pdf
  # PDFs sources chiffrés avec leur propre mot de passe (inline mapping) :
  - {path: confidentiel.pdf, password: secret}
  - {name: backup.pdf, pass: autre-mdp, title: "Annexe sécurisée"}
----

[NOTE]
====
*Sécurité* : laissez les mots de passe **vides** dans le YAML
quand celui-ci est versionné dans Git. Fournissez-les en CLI :

[source,shell]
----
combine-pdf -u 'mdp-sortie' -w 'mdp-owner'  # chiffrement de sortie
combine-pdf -I 'mdp-source-global'          # ouverture sources
----

Les flags CLI surchargent toujours le YAML. Pour un livret avec des
sources qui ont chacune un mot de passe différent, utilisez la
syntaxe inline mapping `- {path: x.pdf, password: y}` ci-dessus.
====

=== Vocabulaire des positions

[cols="1,4"]
|===
| Type de position | Valeurs

| Statique (fixe quelle que soit la parité de page)
| `top-left`, `top-center`, `top-right`,
  `bottom-left`, `bottom-center`, `bottom-right`

| Duplex-aware (alterne par parité de page)
| `outer-top`, `inner-top`, `outer-bottom`, `inner-bottom`
|===

Quand `duplex: true`, `outer-*` se résout au côté opposé à la
reliure (droite pour les pages impaires/recto, gauche pour les
paires/verso). `inner-*` est le côté reliure. Quand
`duplex: false`, `outer-*` ≡ `right`, `inner-*` ≡ `left`.

=== Sémantique de la couverture

* `cover.mode: none` — pas de couverture, toutes les pages
  numérotées (défaut).
* `cover.mode: recto` — 1 page de couverture en début *et* 1 en fin.
* `cover.mode: recto-verso` — 2 pages en début et 2 en fin.
* Pour des couvertures asymétriques, utilisez `cover.front:` et
  `cover.back:` à la place de `cover.mode:`.

Quand `include_in_numbering: false` (défaut), ni les pages de
couverture avant ni les pages de couverture arrière n'affichent de
numéro, et la première page de contenu du livret porte le numéro 1.
`%total%` reflète le total *utile* (sans les couvertures).

=== Signature (`sign` / `verify`)

Après avoir assemblé un document, on peut le signer (PAdES) sans quitter
l'outil. `sign` / `verify` délèguent au binaire `pdf-sign` de
`aloli-crystal/pdf-signature` — tout ce qui suit le verbe est transmis
tel quel, donc l'ensemble des drapeaux (niveaux B-B…B-LTA, horodatage
RFC 3161, LTV, PKCS#11/HSM) est exactement celui de pdf-sign.

[source,shell]
----
export P12_PASS=…                     # la phrase de passe vit dans une var d'env
combine-pdf merge a.pdf b.pdf -o livret.pdf
combine-pdf sign -i livret.pdf -o livret-signe.pdf \
  -c signataire.p12 -p P12_PASS -l b-lt -t https://tsa.example/tsr
combine-pdf verify livret-signe.pdf -a confiance.pem
----

* La phrase de passe / le PIN est donné comme **nom d'une variable
  d'environnement** (`-p P12_PASS`), jamais comme valeur — aucun secret
  n'atteint argv.
* `pdf-sign` est résolu depuis `$COMBINE_PDF_PDFSIG` (chemin explicite)
  ou comme `pdf-sign` sur le `PATH`. Le `pdfsig` de poppler (sans
  rapport) n'est jamais appelé. Installation :
  `ln -s …/pdf-signature/bin/pdf-sign ~/bin/pdf-sign`.

=== Chiffrement

Le shard `aloli-crystal/pdf` (≥ 0.5.2) gère le « Standard Security
Handler » du spec PDF (ISO 32000-1 et 32000-2 § 7.6.4) en lecture ET
écriture, sans dépendance externe. `combine-pdf` expose ces
capacités à trois niveaux : sous-commandes autonomes, section YAML,
flags CLI.

==== Sous-commandes autonomes

[source,shell]
----
combine-pdf encrypt rapport.pdf -u "secret" -l aes_256
combine-pdf decrypt protege.pdf -u "secret" -i --backup
----

* `encrypt` : chiffre un PDF arbitraire (RC4-128, AES-128 ou AES-256).
* `decrypt` : symétrique — produit une version sans `/Encrypt`.

Options communes (héritées de `compress` / `gs`) :

* `-o FICHIER` ou `-i` (in-place) ou nom de sortie auto (`*-encrypted.pdf`,
  `*-decrypted.pdf`) si rien n'est précisé
* `--backup` (avec `-i`) : sauvegarde l'original en `.bak`
* `-l rc4_128 | aes_128 | aes_256` (encrypt seulement, défaut `aes_256`)
* `-u USER_PWD` mot de passe utilisateur, `-w OWNER_PWD` mot de passe owner
* `-p LIST` permissions (csv : `print,copy,modify,annotate` ;
  raccourcis `none` / `all`. Défaut : `all`)

==== Chiffrer la SORTIE d'un build

Section `encrypt:` du `.combine-pdf.yml` :

[source,yaml]
----
encrypt:
  enabled: true                  # `false` désactive la section
  level: aes_256                 # rc4_128 | aes_128 | aes_256
  user_password: "ouvre-moi"     # vide = pas de mot de passe à l'open
  owner_password: "permissions"  # vide ou nil = identique à user
  permissions: [print]           # absent = tout autorisé
  encrypt_metadata: true
----

Niveaux disponibles :

[cols="1,1,3"]
|===
| Niveau     | V/R | Compatibilité

| `rc4_128`  | 2/3 | Acrobat ≥ 5 (1999), legacy uniquement (RC4 est cassé)
| `aes_128`  | 4/4 | Acrobat ≥ 7 (2005), CryptFilter `AESV2`
| `aes_256`  | 5/6 | Acrobat ≥ X / PDF 2.0 (2012), défaut
|===

Surcharges CLI (priorité sur le YAML) :

[source,shell]
----
combine-pdf -u "secret"            # user_password de sortie
combine-pdf -w "owner-pwd"         # owner_password
combine-pdf -l aes_128             # niveau
combine-pdf --encrypt              # active sans la section YAML
combine-pdf --no-encrypt           # désactive même si YAML l'active
----

==== Lire des PDFs sources chiffrés

Cas global (un seul mot de passe pour tous les PDFs sources chiffrés) :

[source,yaml]
----
input_password: "secret-source"
files:
  - confidentiel-1.pdf
  - confidentiel-2.pdf
----

CLI équivalent (utile pour ne pas écrire le mot de passe en Git) :

[source,shell]
----
combine-pdf -I "secret-source"
# ou : --input-password=secret-source
----

Cas par fichier (chacun son mot de passe) — syntaxe inline mapping :

[source,yaml]
----
files:
  - public.pdf                                     # entrée simple
  - rapport.pdf: "Rapport annuel"                  # avec titre
  - {path: confidentiel.pdf, password: "secret-A"} # avec mot de passe
  - {name: backup.pdf, pass: "secret-B", title: "Annexe"}
----

Alias acceptés :

* `path` ≡ `name` ≡ `file`
* `title` ≡ `label`
* `password` ≡ `pass` ≡ `pwd`

Précédence : `entry.password` (per-file YAML) > `input_password`
(global YAML) > `--input-password` CLI > vide.

Le mot de passe owner d'un PDF source fonctionne aussi bien que le
mot de passe utilisateur (le shard `pdf` essaie les deux automatiquement
via Algorithm 7 pour V<5 et Algorithm 2.A pour V=5).

[NOTE]
====
*Recommandation sécurité* : si le YAML est versionné (Git), laissez
les champs `user_password`, `owner_password`, `input_password` et
les `password:` per-file **vides** dans le fichier, et fournissez les
secrets uniquement en CLI. Pour les workflows CI/CD, utilisez des
variables d'environnement et un wrapper shell.
====

==== Empêcher la modification (sans empêcher la lecture)

C'est exactement le rôle des **permissions** côté
chiffrement. Le PDF est lisible par tous (mot de passe
utilisateur vide), mais Acrobat / Foxit / Preview / pdftk refusent
toute modification tant que l'utilisateur n'a pas saisi le **mot
de passe owner**.

Recette :

[source,yaml]
----
encrypt:
  enabled: true
  level: aes_256
  user_password: ""            # ← vide : ouverture libre
  owner_password: "secret"     # ← obligatoire pour modifier
  permissions: [print]         # ← seul l'impression est autorisée
----

Ou en CLI :

[source,shell]
----
combine-pdf encrypt rapport.pdf -w "secret" -p print
----

Permissions disponibles :

[cols="1,3"]
|===
| Permission | Effet quand listée

| `print`    | Imprimer le document (basse + haute résolution)
| `copy`     | Sélectionner / copier du texte ou des images
| `modify`   | Éditer le contenu de la page
| `annotate` | Ajouter ou modifier des annotations (commentaires, surbrillance)
|===

Raccourcis (CLI uniquement) : `none` (aucune permission), `all`
(toutes — équivalent à omettre le flag).

[IMPORTANT]
====
**Modèle de confiance**. Les permissions PDF sont *honor-system* :
le spec demande aux visualiseurs et éditeurs de les respecter, et
Acrobat/Foxit/Preview/pdftk le font effectivement. Mais un attaquant
déterminé peut **stripper le `/Encrypt`** d'un PDF ; les permissions
ne sont pas cryptographiquement appliquées.

Pour une protection cryptographique de l'intégrité, il faut une
**signature numérique** (cf. plus bas).
====

==== Signatures numériques (PAdES) — roadmap

Les signatures détectent toute modification du PDF en s'appuyant
sur la cryptographie asymétrique :

. Le signataire calcule un hash SHA-256 / SHA-384 sur les octets du
  PDF (à l'exclusion de la signature elle-même).
. Il chiffre ce hash avec sa clé privée (PKCS#7 / CMS / CAdES) et
  l'embarque dans un dictionnaire `/Sig` du PDF.
. Tout vérificateur peut recalculer le hash et le comparer au hash
  déchiffré avec la clé publique du certificat.
. La moindre modification (un seul octet) invalide la signature —
  Acrobat l'affiche en rouge.

Différence avec le chiffrement :

[cols="1,1,1"]
|===
|                          | Chiffrement (`/Encrypt`) | Signature (`/Sig` PAdES)
| Empêche la lecture       | ✅                       | ❌
| Détecte la modification  | ⚠️ via permissions      | ✅ (cryptographique)
| Prouve l'authenticité    | ❌                       | ✅
| Long-term archival       | ❌                       | ✅ (PAdES B-LTA)
|===

Niveaux PAdES (ETSI EN 319 142) :

* **B-B** — signature de base (PKCS#7 détaché)
* **B-T** — B-B + horodatage TSA
* **B-LT** — B-T + matériel de validation à long terme (CRL/OCSP)
* **B-LTA** — B-LT + horodatage d'archive (renouvelable indéfiniment)

État actuel d'`aloli-crystal/pdf` : la lecture détecte les `/Sig`
mais ne valide pas la signature ; l'écriture n'en produit pas. Le
support est sur la roadmap (cf.
`prod-crystal/crystal-combine-pdf/ROADMAP.adoc` § « Signatures PAdES »).
Effort estimé : M pour B-B (PKCS#7 via OpenSSL), L pour B-T (TSA HTTP),
XL pour B-LT/LTA (collecte CRL/OCSP, archival).

En attendant : pour un PDF qui doit prouver son intégrité dans un
contexte légal, signer **après** le build avec un outil tiers
(`gpg --detach-sign`, Adobe Acrobat, eSign Suite, etc.).

== Sous-commandes historiques

Les sous-commandes originales `number`, `merge`, `assemble` restent
disponibles pour les workflows scriptés.

=== `assemble` — le workflow livret (le plus courant)

[source,shell]
----
# Prendre trois PDF de partitions, les fusionner, numéroter le
# résultat avec des tailles de partition auto-détectées (donc
# chaque partition reçoit son marquage intra-partition "1/4",
# "2/4" là où c'est pertinent).
combine-pdf assemble \
  partition1.pdf partition2.pdf partition3.pdf \
  -o livret.pdf
----

=== `merge` — concaténation pure, sans numérotation

[source,shell]
----
combine-pdf merge p1.pdf p2.pdf p3.pdf -o sortie.pdf
----

=== `number` — numéroter un PDF déjà assemblé

[source,shell]
----
# Défaut : format "N/T" en bas à droite.
combine-pdf number livret.pdf

# Idem, avec marquage intra-partition. Tailles données dans l'ordre
# 1-based des pages — la somme doit valoir le nombre total de pages.
# Ici : pages 1-4 = partition 1 (donc chacune marquée "1/4" à "4/4"),
# pages 5-6 = partition 2, page 7 = partition 3 (1 page → pas de
# marque intra-partition par défaut).
combine-pdf number livret.pdf --partitions 4,2,1

# Ne pas numéroter la couverture (page 1).
combine-pdf number livret.pdf --skip 1

# Format personnalisé et couleur rouge.
combine-pdf number livret.pdf \
  --global-format "Page %page% sur %total%" \
  --partition-format "(%page% / %total%)" \
  --color "0.7,0.0,0.0" \
  --font-size 12
----

=== Options

[cols="1,3"]
|===
| Option | Description

| `-o FICHIER`, `--output FICHIER`
| Chemin de sortie. Défaut : `<entrée>-numbered.pdf` à côté du
  fichier d'entrée.

| `--partitions N,N,…`
| Liste de tailles de partitions séparées par des virgules, dans
  l'ordre 1-based des pages. La somme doit égaler le nombre total
  de pages du PDF.

| `--skip PAGES`
| Liste de numéros de page (1-based) à laisser non numérotés
  (typique : `--skip 1` pour épargner la couverture).

| `--font-size TAILLE`
| Taille en points des numéros rendus. Défaut 10.

| `--margin PT`
| Marge depuis le bord de la page, en points. Défaut 24.

| `--color R,G,B`
| Triplet RGB, composantes 0.0 à 1.0. Défaut `0.2,0.2,0.2`.

| `--global-format FMT`
| Chaîne de format du numéro global. Substituts : `%page%`,
  `%total%`. Défaut `"%page%/%total%"`.

| `--partition-format FMT`
| Chaîne de format du numéro intra-partition. Mêmes substituts.
  Défaut `"%page%/%total%"`.

| `--show-single-partitions`
| Affiche le numéro intra-partition même quand la partition fait une
  seule page. Désactivé par défaut.

| `-h`, `--help`, `-v`, `--version`
| Standard.
|===

== API

=== API ISO (miroir de la gem Ruby)

[source,crystal]
----
require "combine-pdf"

# Points d'entrée du module
CombinePDF.new                  # => CombinePDF::PDF (vide)
CombinePDF.load(path : String)  # => CombinePDF::PDF (depuis fichier)
CombinePDF.parse(data : Bytes)  # => CombinePDF::PDF (depuis octets)

# API d'instance
pdf << other        # ajoute en fin (chemin ou PDF) — chaînable

=== Helpers bonus spécifiques Crystal

[source,crystal]
----
# Concaténation multi-PDF en une commande
CombinePDF.merge(["a.pdf", "b.pdf"], "sortie.pdf")

# Numéroter un PDF déjà assemblé sur disque
CombinePDF.number(
  input: "livret.pdf",
  output: "livret-numbered.pdf",
  partitions: [4, 2, 1],
  options: CombinePDF::Options.new(
    font_size: 11.0,
    color: {0.2, 0.2, 0.2},
    margin: 24.0,
    skip_pages: [1],
  ),
)

# Assemblage de livret bout-en-bout (fusion + numérotation avec
# tailles de partitions auto-détectées — chaque fichier d'entrée =
# une partition)
CombinePDF.assemble(
  inputs: ["partition1.pdf", "partition2.pdf", "partition3.pdf"],
  output: "livret.pdf",
)
----

== Limitations (v1.0.31.1)

* Pas de déduplication des ressources communes lors de la fusion —
  une police ou image embarquée dans N PDF source est copiée N fois
  dans la sortie. Résultat correct mais légèrement plus volumineux
  qu'un merger optimisant. Visé pour la v0.3.
* La numérotation est rendue avec le `Helvetica` standard Type1 (pas
  de police embarquée, pas d'Unicode au-delà des chiffres ASCII et
  du `/`).
* La sortie de `number` est une **mise à jour incrémentale** (spec
  PDF § 7.5.6) ; `merge` et `assemble` écrivent un PDF neuf depuis
  zéro. Les deux sont gérés correctement par `pdf::Reader`
  v0.3.4+ et tous les lecteurs PDF du marché.
